# Lista 03: Arrays, Classes e Objetos
## Questão 4
### a) Como a memória é alocada em cada caso?

Nos arrays de tipos primitivos, como `int[] notas = new int[3]`, o `new` reserva no heap um bloco contínuo com espaço para os três valores, e cada posição já começa com o valor padrão do tipo (0 para `int`, 0.0 para `double` e `false` para `boolean`). Os valores ficam guardados dentro do próprio array, então quando eu faço `notas[0] = 10` o número 10 é gravado direto naquela posição. Por outro lado, já no array de objetos, como `Aluno[] alunos = new Aluno[3]`, o `new` reserva apenas um bloco de referências, e todas elas começam com `null`. Assim, nesse momento nenhum objeto `Aluno` foi criado. Cada aluno precisa ser criado com o seu próprio `new`, por exemplo `alunos[0] = new Aluno("Bruno", "2024001")`, e esse objeto fica em outro ponto do heap, enquanto a posição do array guarda só o endereço dele. Então, no array de primitivos o acesso vai direto ao valor, e no array de objetos existe um passo a mais, porque o array aponta para o objeto e é o objeto que tem os dados.

### b) Cuidados ao acessar elementos de um array de objetos

No que diz respeito ao cuidado ao acessar elementos em um array de objetos, o principal cuidado é com o `null`. Como criar o array não cria os objetos, se eu tentar usar `alunos[1].getNome()` antes de fazer `alunos[1] = new Aluno(...)`, o programa lança uma `NullPointerException`. Por isso é preciso instanciar cada posição antes de usar, ou então testar se ela é diferente de `null` (isso aparece também quando o array não está cheio). Na classe `Turma`, da questão 1, guarda-se um contador (`qtdAlunos`) e os `for`s vão só até ele, ao invés de ir até `alunos.length`, justamente porque as posições que sobram ainda são `null`. além disso, outro cuidado é com os limites do array, que vão de 0 até `length - 1`. Pois, acessar uma posição fora disso gera uma `ArrayIndexOutOfBoundsException`, e por isso o método `adicionarAluno` confere se ainda existe espaço antes de inserir o aluno. Além disso, também é preciso lembrar que atribuir um elemento a outro copia só a referência, e não o objeto. Se eu fizer `alunos[1] = alunos[0]`, as duas posições passam a apontar para o mesmo aluno, e uma alteração feita por uma posição aparece na outra. O mesmo acontece com `Aluno[] outro = alunos`, em que as duas variáveis apontam para o mesmo array. Para ter objetos independentes é preciso criar novos com `new`. Por fim, por causa da herança e do polimorfismo, um array do tipo da superclasse, como `Pessoa[]`, pode guardar objetos das subclasses, como `Aluno` e `Professor`. Ao acessar `pessoas[i]` só posso chamar os métodos que existem em `Pessoa`, mas o método que realmente executa é o da classe real do objeto. Para usar algo que só existe na subclasse é preciso verificar o tipo com `instanceof` e fazer o cast, senão pode acontecer uma `ClassCastException`.
